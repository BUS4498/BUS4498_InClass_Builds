# Student mail category policy

The sorting model chosen during the build proposes **one primary category** per message from these options. The controller maps a valid, clear choice to one app-owned Gmail label; these are separate from Gmail system categories.

| Choice ID | Gmail label | Include when the main purpose is |
| --- | --- | --- |
| `personal` | `Student/Personal` | Direct correspondence with friends, family, or other personal contacts. |
| `course_work` | `Student/Course Work` | Classes, assignments, instructors, study groups, course meetings, advising, or course deadlines. |
| `jobs_interviews` | `Student/Jobs & Interviews` | Jobs, internships, applications, interviews, recruiting, or career preparation. |
| `finance` | `Student/Finance` | Tuition, aid, scholarships, bills, payments, refunds, or other financial actions. |
| `others` | `Student/Others` | Campus events, registration, housing, records, newsletters, promotions, or anything outside the four categories above. |

The controller routes missing, invalid, conflicting, or uncertain sorting output to **Needs review** in the app; it does not apply a Gmail category label for that result. `Needs review` is a status, not a sixth model choice. A clear result requires exactly one valid category ID, a valid uncertainty signal defined for the chosen model, and no uncertainty flag. During the Build Agent tool plan, define and test how that model expresses uncertainty. If reliable category probabilities are available, a proposed starting rule is top-choice probability at least `0.80` and at least `0.15` above the second choice. If probabilities are unavailable or not meaningful, use a documented provider-appropriate review signal and omit probability bars. A model that cannot support a credible clear-versus-review decision must not silently auto-label; select a different route or send its choices to student review. The student can correct results after the sorting run stops. Needs review also groups unresolved label failures and unprocessed items in the interface; these are not additional model category choices.

For overlap, classify by the message's main requested action or information, not by the sender alone. A university tuition bill is `finance`; a university career-office interview invitation is `jobs_interviews`; a class announcement that mentions a campus event is `course_work` if the course is its main purpose. The student can override any label, including a clear choice. A correction replaces only another app-owned `Student/` category label on that message and never changes unrelated Gmail labels. A correction becomes a saved override only after successful verified labeling (or fictional simulation). A later sort run preserves a valid override without rewriting or rechecking the Gmail label; its status is preserved correction, not newly verified labeling. If a future taxonomy removes a choice ID, the saved correction remains stored and the student reviews a new category before any Gmail label change.

The sorting model also returns a separate **reply urgency** estimate on this five-level rubric: 0 no reply called for, 1 optional reply, 2 explicit reply with no near deadline, 3 reply soon for coordination or an explicit deadline within several days, 4 explicit today/tomorrow reply deadline or immediate consequence. The app displays a validated 0–100 estimate; an integer level maps to 0, 25, 50, 75, or 100, while a selected model with a validated continuous score may use intermediate values. The Build Agent tool plan must document the mapping before implementation. This is not a verified deadline, importance measure, or proof that a reply is needed. Missing or invalid urgency output is shown as unavailable and does not erase an otherwise valid category choice. Opening the live inbox initiates sorting for its newest 15 messages; a saved correction can retain its category while the model estimates urgency. If meaningful category probabilities are available, show them separately as confidence bars; never present them as correctness or as the reply-urgency score.
