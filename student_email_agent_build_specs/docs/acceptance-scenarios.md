# Acceptance scenarios for a later build

These are reproducible review scenarios, not a claim that every live operation has been tested. Use labeled fictional fixtures first. Live checks need the student's configured account and selected providers. The model-choice stage records actual API contracts, uncertainty handling, and bounded provider timeouts without prescribing model names here.

| ID | Trigger | Expected visible outcome |
| --- | --- | --- |
| A1 | Open the app before OAuth | Disconnected; live inbox and live send unavailable. Sample mode works without Gmail or model calls. |
| A2 | Click **Open & sort live inbox** beside account controls | Retrieve one metadata window capped at 15 newest inbox messages, then bounded text for eligible records. Sorting starts without another confirmation; no older-page cursor or inbox-preview panel. Model input omits HTML and attachments. |
| A3 | Clear model choice with no saved correction | T3 applies one registered app-owned category label and verifies it by read-back, retaining unrelated labels. A failed or unknown operation is not labeled successful. |
| A4 | Uncertain/invalid model choice, unavailable provider, or missing sorting text | Needs review with the reason; no new category label. Continue other messages without waiting for student review. Missing urgency alone displays unavailable and does not erase a valid category. A valid saved override follows A17. |
| A5 | Change category after sorting stops | Selection invokes T3 immediately without a confirmation button. Persist an override only after verified live or simulated success. Reject stale decision versions and review during active sorting. |
| A6 | Click Reply, set intent and tone, and Generate reply | Show exact bounded thread first: up to three messages ending at the selected email, at most 4,000 characters each. Require intended answer or acknowledgment-only choice. Use the five-position Professional-to-Warm slider with Balanced default. Generate returns an editable saved draft or an explicit error; it never sends. No separate Write manually button. |
| A7 | Edit body/recipient or resolve missing questions | Changed values must be saved before sending; saving clears prior authorization. Unresolved placeholders block send. Missing-question acknowledgment must be saved where required. An unchanged eligible generated draft needs no extra Save edits action. |
| A8 | Click Send this reply, then Cancel or Confirm and send once | First show exact recipient, fixed subject, and body. Cancel returns to review without authorization/send. Final confirmation authorizes one send. Multiple Reply-To candidates require one choice; invalid/self addresses block send; no-reply requires acknowledgment. Show sent evidence or failed/unknown outcome. |
| A9 | Gmail send response is uncertain | Reconcile exact outbound Message-ID, thread, and SENT label through bounded reads. If unresolved, show unknown and block resending. Check Gmail Sent again is read-only. |
| A10 | Empty inbox, expired OAuth, or provider failure | Show actual empty/error status and recovery action, with no fabricated live results. Individual metadata failures are excluded from sorting eligibility; selected-body failures enter Needs review. |
| A11 | Leave a category unresolved and reopen Review pending categories | Resume saved account/mode/message/version records without reclassifying the batch. Choosing a category invokes T3. Review later leaves Gmail unchanged; Skip is offered only before any label operation has started. Reply is disabled for a saved item outside the current retrieved batch. |
| A12 | Cancel during processing, reach a processing limit, or request a fourth draft attempt | Remaining sorting items are unprocessed; completed labels remain. Preparation and in-flight requests may finish. Fourth draft attempt is blocked; existing draft remains editable. Restart does not automatically resume interrupted sorting. |
| A13 | Inspect local pilot metrics | Category agreement uses explicit review feedback with a valid proposed category. Draft acceptance uses final send authorization and at most one saved body change among generated-draft runs ending sent, discarded, failed, or unknown. Pending/no-draft cases are separate. No pilot-measures panel and no invented baseline. |
| A14 | Sort fictional/current inbox and click category bars | Animated category bars sit beside the urgency panel. No cards until a bar click; current-batch matching cards appear in descending urgency, unavailable last. Each has a Reply control; Needs review is separate. Clear selection hides cards. Optional confidence bars use valid meaningful model probabilities. Keyboard, reduced-motion, and narrow-screen layouts work. Saved pending queues use saved-record ordering. |
| A15 | Saved correction uses a removed category ID | Preserve the old saved value and Gmail label; enter Needs review for a new choice without silent relabeling. |
| A16 | Connect Gmail without opening the inbox | Show account status and wait. No inbox, sorting, or new drafting begins. New reply requires Open & sort live inbox, a category click, Reply, then Generate. Saved credentials on startup are distinguished from an account verified this session. |
| A17 | Sort a message with a valid saved category correction | Retain the corrected category while estimating urgency; make no T3 write or Gmail label recheck. Report preserved correction/not rechecked. A provider failure retains the correction and makes urgency unavailable. |
| A18 | Open pending replies and request Generate another reply | Reopen the saved run without retrieving another inbox/thread. Show saved text and intent/tone controls, reuse the existing snapshot and attempt budget. Save edits/Keep pending do not send; Discard closes the draft. |
| A19 | Definite send failure versus restarted in-flight send | Definite failure can reopen saved review and requires fresh final confirmation before another send. An interrupted sending operation becomes unknown; only reconciliation is available, with no automatic send retry. |
| A20 | Gmail contains a same-name label outside the ownership registry, or an owned label was renamed/deleted | Block label mutation with a clear error; do not adopt or remove an unrelated label based on its name. |
| A21 | Reply to a current-batch message in Needs review or with failed labeling | Category success is not a reply prerequisite. Still require usable selected-thread context, valid recipient, resolved draft, and final send confirmation. |
| A22 | Disconnect and reconnect the same account | Clear local credentials/current batch and attempt revocation. Retain account-scoped saved work. Reopen saved reviews after reconnecting; do not automatically retrieve the inbox or resume sends. |

The category-agreement denominator is explicit reviewed feedback with a valid proposed category, not every automatically sorted message. A saved correction preserved in a later run contributes no new proposed-category review. Draft acceptance is recorded at final send authorization; it does not prove delivery. The draft edit count counts changed saved bodies, not keystrokes. Targets of 85% category agreement and 75% draft acceptance remain goals until a user-reviewed pilot measures them.
